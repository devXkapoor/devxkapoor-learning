Node 42 — the history, threaded in order

The limitation: the dates and names in this document have arrived one at a time, attached to mechanisms. In order, they make a story that is far easier to hold than forty separate facts.

Before there is anything (1936–1949)

1936 — Alan Turing's paper on computable numbers describes a universal machine: one device that can simulate any other, given a description of it on its tape. The idea that a program is data predates any hardware capable of it.

1945 — the First Draft of a Report on the EDVAC (Node 0), circulated under von Neumann's name, records the stored-program design.

December 1947 — the transistor, at Bell Labs.

1948–49 — the Manchester Baby runs the first stored program (21 June 1948); EDSAC at Cambridge runs the first practically useful one (6 May 1949).

Machines with no operating system (1950s)

Sign-up sheets, punched cards, one program at a time, an operator walking across a room between jobs (Node 0). 1956 — GM-NAA I/O, the resident monitor, for the IBM 704 (Node 1). 1957 — FORTRAN makes programs something written rather than wired.

Every idea in this document is invented (the 1960s)

The decade that matters most. Nearly everything in Parts I–III originates here.

1961 — CTSS at MIT, Fernando Corbató: genuine interactive time-sharing, and the multi-level feedback queue (Node 7). Also the first computer password, and — within a few years — the first password leak.

1962 — the Ferranti Atlas at Manchester, Tom Kilburn: interrupts with priorities, extracodes (system calls, Node 4), a Supervisor program, and virtual memory with demand paging (Node 10) — a decade before commercial machines adopted it. The most under-credited machine in computing.

1964 — IBM System/360: one architecture across a whole product line, the 8-bit byte standardised (Node 0), and OS/360 with JCL (Node 1). Fred Brooks managed it and wrote The Mythical Man-Month (1975) about what went wrong.

1965 — Multics begins (MIT, Bell Labs, GE): protection rings (Node 3), a hierarchical filesystem, memory-mapped files, dynamic linking, and security as a first-class goal. Ambitious, late, and slow.

1965 — Dijkstra's semaphores (Node 17). 1968 — Denning's working set (Node 13).

Unix (1969–1979)

1969 — Bell Labs withdraws from Multics. Ken Thompson, wanting to run a game called Space Travel, writes a small system on a spare PDP-7. Dennis Ritchie joins. Brian Kernighan names it Unics, a pun on Multics; it becomes Unix. 1 January 1970 becomes the epoch (Node 8).

1972–73 — Ritchie creates C, and in 1973 Unix is rewritten in it. This is the decisive moment: an operating system in a high-level language can be moved to a new machine by writing a compiler, and portability is what actually spreads Unix. The 1974 CACM paper by Ritchie and Thompson makes it famous.

A 1956 antitrust consent decree bars AT&T from selling computer products, so Unix is licensed to universities for a nominal fee with source. A generation learns operating systems by reading it — including John Lions's commentary, which AT&T then restricted, making it the most photocopied document in computing.

1977 — Bill Joy at Berkeley ships the first BSD.

Divergence and standardisation (1980s)

1981 — IBM PC and MS-DOS. 1982 — the 80286 brings protected mode; 1985 the 80386 completes it (Node 3).

1983 — 4.2BSD: the socket API and TCP/IP (Node 32), which is why the internet speaks Unix. The same year, Richard Stallman announces GNU — a free Unix — producing GCC, Emacs, and the utilities, but never finishing its kernel, Hurd.

1987 — Andrew Tanenbaum releases Minix as a teaching system. 1988 — POSIX.1 standardises the Unix interface, so that the diverging BSD and System V worlds share a portable core; it is why your code compiles on Linux and macOS.

1989 — NeXTSTEP, built on Mach and BSD, which will become macOS twelve years later.

Linux (1991–1999)

25 August 1991 — Linus Torvalds, 21, posts to comp.os.minix: "I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu)". Version 0.01 in September.

1992 — relicensed under the GPL, which is what makes contribution safe and is arguably as important as the code. The same year, the Tanenbaum–Torvalds debate (Node 41). Also 1992: AT&T's lawsuit against BSDi and Berkeley puts the BSDs under a legal cloud for two years — exactly the window in which Linux gathered its community. It is entirely plausible that Linux won because BSD was in court.

1993 — Windows NT 3.1 (Dave Cutler), FreeBSD and NetBSD, Debian and Slackware. 1994 — Linux 1.0. 1996 — Linux 2.0 with multiprocessor support. 1998 — Netscape opens its source; the term "open source" is coined; IBM and Oracle back Linux.

The infrastructure era (2000–2012)

2001 — Mac OS X: NeXTSTEP's XNU kernel makes Unix the desktop system of a mass-market vendor.

2003 — Linux 2.6: the O(1) scheduler and NPTL 1:1 threads (Node 15). 2004 — nginx (Igor Sysoev), written against the C10K problem (Node 18); Ubuntu.

2005 — Intel VT-x and AMD-V make hardware virtualisation practical (Node 29). Also 2005: Torvalds writes Git in ten days after BitKeeper's licence is withdrawn.

2006 — Amazon EC2. Virtualisation plus a credit card. The economics of computing change.

2007 — Android is announced and the iPhone ships; both run Unix-derived kernels, so the mobile era is Unix too. 2008 — cgroups merged into Linux 2.6.24 (Node 27), from Google, who had been running containerised workloads internally for years.

November 2009 — Ryan Dahl presents Node.js at JSConf EU (Node 18). 2010 — systemd (Node 37).

Containers and the present (2013–)

March 2013 — Solomon Hykes demonstrates Docker in a five-minute lightning talk at PyCon. Every kernel feature it used already existed — namespaces since 2002, cgroups since 2008, union filesystems for years. Docker's contribution was the image format, the registry, and the developer experience, and that is a genuine and sufficient contribution: it made an assembly of existing kernel features into something a working developer could use in an afternoon.

June 2014 — Google announces Kubernetes, distilled from its internal Borg system. 2015 — the OCI standardises the image and runtime formats; the CNCF is founded. 2016 — BBR congestion control (Node 32).

January 2018 — Meltdown and Spectre (Nodes 0, 40). The first time a processor optimisation forced a redesign across every operating system, browser and cloud simultaneously. November 2018 — Firecracker (Node 29). May 2019 — io_uring (Node 40).

2020s — cgroups v2 becomes the default; eBPF becomes mainstream infrastructure (Node 39); Rust is accepted into the Linux kernel (6.1, December 2022); Java 21 ships virtual threads (September 2023, Node 18); Linux 6.6 replaces CFS with EEVDF (October 2023, Node 7).

Three patterns in the history

The ideas were finished by 1970; everything since is engineering and economics. Virtual memory, time-sharing, interrupts, protection rings, semaphores, the process model, the file abstraction — all 1960s. What changed afterwards was scale, cost, and who was allowed to use them.

Licensing decided outcomes at least as much as design. The AT&T consent decree spread Unix. The GPL made Linux safe to contribute to. The BSD lawsuit cost BSD its moment. CDDL keeps ZFS out of the kernel to this day. None of that is technical, and all of it shaped what you run.

Simple things that ship beat elegant things that do not. Unix over Multics, Linux over Hurd and Minix, Docker over the seven prior container systems, JavaScript over every better-designed language proposed for the browser. This is not an argument against elegance; it is an observation about what actually determines adoption, and it is worth carrying into your own engineering judgement.

What's still broken: nothing. One trace remains — a single user action, followed through every mechanism in this document at once.
