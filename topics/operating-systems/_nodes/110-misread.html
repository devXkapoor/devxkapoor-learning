Where the chain gets misread

Each item is a belief that is common, wrong, and costly, with the correction and the node where the model actually broke.

"The kernel is a program running alongside my program." It is a mode the processor is in. Your process executes kernel code, on its own time, with the privilege bit raised. There is no kernel process to schedule against. This is why sy time in top is charged to your process, and why a kernel bug panics the machine rather than crashing a process. (Node 3)

"Blocking wastes CPU." A blocked process consumes exactly zero processor time — it is in state S, off the run queue. The cost of blocking is not cycles; it is that this thread can do nothing else, so serving many clients needs many threads, and threads cost memory, scheduler entries, and context switches. The event loop's advantage is that it replaces a context switch with a function call — three orders of magnitude — not that it stops some waste. (Nodes 6, 18)

"Node is single-threaded, so it uses one core." Your JavaScript runs on one thread. The process has a libuv threadpool, V8 compiler and GC threads, and any addon threads, and the kernel scheduler will run them on other cores. A Node process routinely exceeds 100% CPU. (Nodes 7, 15)

"JavaScript is single-threaded, so I don't have concurrency bugs." You do not have data races. You absolutely have race conditions, because every await is a yield point at which other code — including another invocation of the same function — runs against the same state. Read-check-write across an await is exactly the interleaving bug from threaded code. (Node 16)

"A container is a lightweight VM." It is an ordinary process with namespaces, a cgroup, and a layered root filesystem. It shares the host kernel; there is no guest kernel, no boot, no hypervisor. This is why it starts in milliseconds and why a kernel vulnerability is a shared vulnerability. (Nodes 26, 28, 29)

"Free memory should be high." On Linux, unused memory is used for the page cache, and that is correct — cached pages are instantly reclaimable and save disk reads. Read available, not free. (Node 13)

"My process is leaking — RSS went up and never came down." Allocators do not usually return freed memory to the kernel; it goes back to their own free lists for reuse. RSS is a high-water mark. A genuine leak is a continuously rising curve under steady load, not a plateau after a spike. (Node 12)

"heapUsed is my process's memory." It is V8's managed heap only. Buffers, ArrayBuffers, native addon allocations, the binary, shared libraries, code space, thread stacks and allocator fragmentation are all outside it, and all of them count towards the container limit. A buffer leak shows as rising RSS with a flat heap and is invisible in a heap snapshot. (Nodes 11, 12)

"A high load average means the CPU is busy." On Linux, load average counts running and uninterruptibly-sleeping tasks. A machine with a hung disk shows a load of 40 with idle processors. Load average is not a CPU metric on Linux. (Nodes 5, 38)

"Setting a CPU limit protects my service." A CPU limit is a hard quota enforced by stopping every thread until the next period. It causes latency spikes at moderate average utilisation and cannot make anything faster. Requests give you a guaranteed share; limits only add throttling. (Nodes 7, 27)

"OOMKilled means my app has a memory leak." It means the cgroup's memory budget was exceeded, which includes page cache from the container's own file writes and tmpfs contents. A container that logs heavily to a file can be killed with a perfectly flat heap. Check memory.stat for the anon/file split. (Nodes 13, 24, 27)

"The container takes ten seconds to stop." It ignored SIGTERM and was SIGKILLed at the deadline — because PID 1 does not receive signals with default actions unless it installs a handler, or because a shell is PID 1 and does not forward them. (Nodes 5, 30)

"write() returning means the data is saved." It means the bytes are in the page cache. They survive a process crash and are lost on power failure until fsync forces them through the kernel and the device's own write cache. Every database durability setting is a decision about how often to make that call. (Node 23)

"setTimeout(fn, 0) runs it immediately." It is clamped (1 ms in Node, 4 ms in browsers after five nested levels), it waits for the loop to reach its timers phase, and it queues behind any running callback. Timers guarantee a minimum, never a maximum. For "as soon as this callback finishes", use a microtask; for "after I/O", setImmediate. (Nodes 8, 20)

"Date.now() is fine for measuring how long something took." It is a wall clock and can jump forwards or backwards when NTP corrects it, so a duration can come out negative. Use performance.now() or process.hrtime.bigint(), which are monotonic. (Node 8)

"fork() in Node means the fork() system call." cluster.fork() and child_process.fork() spawn a fresh node process via posix_spawn and execve. The real fork() is unsafe in a multithreaded process, because only the calling thread survives while every lock the others held stays locked forever. (Node 14)

"Alpine is just a smaller image." It is a different C library. Binaries are not interchangeable, prebuilt native modules often do not apply, DNS resolution behaves differently, the default thread stack is far smaller, and allocation-heavy multithreaded workloads can be measurably slower. Sometimes worth it; never free. (Node 34)

"os.cpus().length tells me my container's CPU allocation." /proc/cpuinfo is not namespaced, so it reports the host's cores. Limits live in cgroup files. Use os.availableParallelism(). (Nodes 26, 38)

"Deleting a file frees the disk space." unlink removes a name and decrements a link count. The data is freed only when the count reaches zero and no process still holds it open — which is why deleting a log file a running process has open frees nothing and du and df disagree. (Node 21)

"Bundling and linking are different things." They are the same thing. Modules are object files, imports are undefined symbols, tree shaking is dead-code elimination, source maps are debug info, two copies of React is a multiple-definition error the module system declines to report. (Node 33)

"A Kubernetes Service load-balances my requests." It rewrites packets in the kernel, per connection. A long-lived HTTP/2 or gRPC connection pins to one pod for its lifetime, so traffic distributes badly without client-side balancing or a mesh. (Node 32)

"A distributed lock is a lock." A process holding one can be paused by GC, throttling, or a partition for longer than the lease, after which two holders believe they hold it. Without fencing tokens rejected by the storage layer, it reduces contention rather than guaranteeing correctness. (Node 17)
